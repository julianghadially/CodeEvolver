# Macro-approach catalog: hover

## Macro approaches

### M1: Reasoning steps - Breaking the workflow into separate LM calls for different reasoning steps
Description: A new stage upstream of the main step whose output feeds its reasoning logic. For example (but not limited to), running an analysis before generating a query. Calls that check, critique, repair, retry or tie-break an existing output don't count; a call covered by a more specific entry counts only there.

### M2: LM reranker techniques for final document selection
Description: After retrieval and fusion, an LLM reranker semantically ranks candidate documents by claim-relevance and selects the final 21, operating on a numbered list of candidates with short snippets. Some variants protect a high-rank core and only re-rank the tail.

### M3: Deterministic rules for forming queries e.g. parsing rules for query generation
Description: Example: Queries are generated by deterministic keyword rules matching claim patterns—e.g., detecting a year plus sports keywords to emit '<year> <entity> season', music keywords to emit '<entity> discography', death keywords to emit 'Death of <entity>'. No LLM call or passage analysis is involved. Deterministic rules for other portions of the system are most likely incremental unless covered below. 

### M4: Claim decomposition into multiple targeted queries
Description: Instead of using the raw claim as a single retrieval query per hop, an LLM decomposition step analyzes the claim and generates queries (e.g., entity-name or keyword sub-queries), each targeting a specific Wikipedia article. These could be retrieved in parallel, replacing the sequential single-query-per-hop pattern.

### M5: Scoring algorithm for ranked result merges
Description: Instead of concatenating documents from each hop, results from all queries are merged via a scoring algorithm (Reciprocal Rank Fusion, best-rank/MAX scoring, or two-tier blends) with title-based deduplication, and the top 21 are selected by fused score rather than insertion order.

### M6: Entity extraction from passage text for follow-up queries
Description: Entity names are extracted directly from the body text of retrieved Wikipedia passages—using regex (quoted strings, capitalized phrases), an LLM that reads passage bodies, or a hybrid where regex candidates are presented to an LLM for selection—and used as follow-up retrieval queries. 

### M7: Removal of summary step 
Description: Remove the seed program's lossy summarization step that drops entity names
